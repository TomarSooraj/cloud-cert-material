IMP protocols used:

app layer - http/s, smtp -> make REST API calls and send emails; http stateless req/resp, https secure ver of http certs used, smtp for email, ftp files
transport layer - tcp, tls, udp -> are bits and bytes transferred properly(resp for); rel>perf for tcp, secure tcp is tls, perf>relia for udp
n/w layer - ip -> bits and bytes(packets); unreliable

each layer uses layers beneath it

some high perf app talk at n/w layer directly, most talk at app layer
eg: Gaming apps, video streaming apps - sac rel for perf

imp concepts:

avail - access data when needed, 4 9's of avail isvv good => 4.5 mins of downtime in a month, 99.95 is 22 mins, 5 9's is 26s

RTO - Recovery Time Objective => max acceptable downtime

RPO - Recovery Point Objective => max acceptable period of data loss
v small rpo and rto - hot standby and auto failover
v small rpo and some rto - warm standby w/ min infra standby and scale it up when failure happens
v low rpo and long rto - reg data snapshots, trans logs, 
good rpo and rto - Fo to new server

consis - mult dbs updated simul, 

strong consis - sync replications to all replicas, slows down all trans
eventual consis - async repli, lil lag before changes avail in all replicas, diff replicas might ret diff values, eg: social media
read-after-write consis - inserts immed avail, updates are eventual

transactions

db snapshots, safety but makes db slow lil bit
transaction logs, apply transac logs to last snapshot and be upto point
